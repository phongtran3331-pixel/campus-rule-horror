
## 一、基调

这所学校怪，但没人觉得它怪。所有不正常的东西都以最正常的口吻写出来。


**对抗性游戏特调（很重要）**：这是人和人斗的游戏，玩家的心力要花在读其他玩家身上，不是解读环境。
所以探索文本**不承担谜题功能**：

- 写"是什么"，不写"意味着什么"。反常直接摆出来，一句话说完，不暗示背后有秘密。
- 禁用一切引导深究的句式："每次看形状都不太对""多出来的那个字""背面还有一层""像是想告诉你什么"——这类钩子会把玩家拽进解谜心态。
- 结果文本的落点优先是**处境和物资**（你获得了什么、你现在在哪、接下来方不方便），不是"你发现了一个秘密"。
- 怪谈质感保留，但每条读一遍就完，不需要记笔记、不需要联想。玩家中午讨论时最多说一句"我在保安室看到个怪东西"，而不是拿它当证据推理。
- 选项写动作和应对（"放回去""绕开走""先离开"），不写调查和研究口吻（"研究一下刻痕"×）。

## 二、铁律
1. **长短不一。** 15~60 字，绝大多数 20~40 字。允许偶尔一句话只有十来个字（"讲台上有半杯水。"），也允许偶尔写到五六十个字。**绝对不要每条都 30 字左右——那是 AI 味的第一来源。**
2. **角度轮换。** 同一个场景，几条事件要换着视角写：
   - 纯感官（看见的/听见的/摸到的）
   - 动作（你做了 X）
   - 对话碎片（墙上的字、纸条、广播半截话、不知谁说的一句）
   - 规则文本引用（值日表、告示、登记表，照抄格式）
3. **口吻轮换。** 不要一个腔调写到底：
   - 白描（约 40%，默认腔）
   - 日常碎碎念（约 15%，学生口吻的小抱怨、小嘀咕）
   - 校园黑色幽默/玩梗（约 %，苦中作乐，不烂俗）
   - 一瞬间的温情或怅惘（约 10%，尤其教室、树林、操场类场景）

## 三、禁用清单（AI 腔特征）

- ❌ "仿佛 / 似乎 / 宛如 / 犹如" 密集出现（全文最多出现一两次）
- ❌ 每条都用"但 / 却 / 可是"收尾反转
- ❌ 排比、对仗、四字成语堆叠
- ❌ "有什么东西在暗处注视着你"
- ❌ 结尾总结句："这一切，太不寻常了。"
- ❌ 每句一个"像"字比喻。不要出现太多一

## 四、示例（照这个感觉写）

**冷静白描**
> 值日表贴在门后。今天的日期被人用指甲划掉了。
"你感到一阵莫名的寒意/恐惧/不安"
> 讲台上有半杯水。

**日常碎碎念**
> 自动售货机又卡货了。你拍了两下，它掉出来两瓶——都不是你按的那个。

**黑色幽默 / 玩梗**
> 小票上只有一行：确认单。你确认了什么不重要，重要的是它来确认你了。

> 广播响了：请没到的同学抓紧时间，不要到场。

**温情 / 怅惘**
> 课桌右下角刻着"加油"。刻痕很旧，后来的无数道刻痕都绕着它走。

**对话碎片 / 规则引用**
> 墙上贴着告示：晚自习期间，请保持安静，即使只有你一个人。

**动作后果**
> 你把柜门关上了。隔了两秒，里面传来翻书声。

## 五、物品描述重写专项规则

在以上铁律基础上：

1. 保留原 Wiki 的物品名、价值、负重、效果、来源，**只重写"描述"列**。
2. 描述长度跨度拉大：最短的可以 8~10 个字（"缺了三颗齿。梳头会多几根别人的头发。"），最长的可以到 50 字以上。高价值物品可以写得郑重，小垃圾可以写得敷衍甚至吐槽。
3. 角度按物品气质选：外观党（文具、饰品）写触感与痕迹；吃的写味道和后果；规则类物品（值日表、袖章）直接引用文本最有味道。
4. 关键道具（钥匙、杠铃杆、通行卡等）描述里保留用途信息，但不写成说明书，一句话带过。
5. 玩梗比例比普通事件略高（学生捡到东西的口吻），严肃物品（金戒指、名牌钢笔）保持克制。

**重写示例**

| 物品 | 旧（AI 味：均匀、必反转） | 新 |
|---|---|---|
| 磨损的硬币 | 边缘磨圆了，图案只剩模糊的轮廓。放在桌上，过一阵子会变成背面朝上。 | 磨得只剩一圈边。你把它立在桌上，去上了个厕所，回来它倒了，背面朝上。 |
| 超市小票 | 字迹褪得看不清。商品栏只有一行字：确认单。 | 就一行：确认单。买没买东西不重要，重要的是它确认你来过。 |
| 翡翠吊坠 | 对着光看，里面像封着一小片树叶。贴身的时候是温的。 | 光一透，里面封着片叶子。贴着心口放，冬天也是温的。卖家说是残次品。 |
| 驱蚊水 | 喷出来有很重的草药味。喷过的地方，蚊子不落。 | 味儿冲得呛眼。喷过之后蚊子确实不来了——别的东西也没有。 |
| 半块橡皮 | 半块橡皮，指印陷得很深。用它擦过的纸面会留一个浅窝，大小跟拇指差不多。 | 被人攥得变了形。擦字倒是干净，就是纸会留个浅浅的指窝。 |

## 六、事件文本输出约定（选项 + 结果 结构）

每个节点不是一段连续文本，而是**选项驱动的分支结构**：

- **P（子位置）= 场景描述 `situation`**：玩家进入该位置时看到的一段话，30~60 字，定场用。
- **Y（事件节点）= 选项 + 结果**：
  - `choice`：选项文本，**不超过 15 字**，动词开头的短语（"翻开讲台抽屉""跟上去看看""装作没听见"）；
  - `result`：选中后发生的文本，15~60 字，遵循前五章全部风格铁律。
- **Y 的子节点 = 该结果之后出现的下一层选项**。有子 Y 就继续选；无子 Y（END）则事件链收束，result 写得有收束感。
- 同一父节点下的多个子 Y = 并列的可选项，写成同一局面的不同走向。
- 每个子位置（P）至少有一条选项链；选项总数就是 Y 的数量，**一条都不许漏**。

程序回填格式（JSON）：

```json
{
  "situations": {"P1": "器械区的灯坏了一半。铁器堆在墙角，谁用完都没放回去。", "P2": "……"},
  "events": {"Y1": {"choice": "查看铁器堆", "result": "哑铃按重量排成一列。中间缺了一个位置，灰里有新近压过的痕。"}, "Y2": "……"}
}
```

- 允许在 result 中嵌入掉落标记 `[[物品名]]`（物品名必须从《物品 Wiki》里选），程序会将其剔除并把该物品加入掉落。每 5~8 条 result 最多用一个标记，别条条掉东西。
- 不出现"自管委""理事长"字样的剧透；可以出现"袖章""值周生""广播"这类元素。
- 选项文本可以玩梗、可以口语（"先跑为敬"），但同一批选项别都是同一种句式。

## 七、深入探索（答题节点）【定稿】

挑战类事件链的末端挂一个**答题节点**：出题 → 玩家选项作答 → 对/错结算。

**两类题目：**

1. **静态题**：脑筋急转弯、高等数学、校史冷知识。设计时预设正确选项（`answer` 为选项下标）。
2. **动态局势题**：如「现在还有几个人活着」「这个房间里现在有几个人」「今天广播通报过几次」。**没有预设答案**，以答题提交那一刻的真实局势结算。计数标准：**答题者本人计 1，每多一名符合题面条件的玩家 +1**，即正确答案 = 触发瞬间的真实计数。

**结算规则：**

- 答对：奖励**高价值物品**（从《物品 Wiki》高价值栏选，不用 `[[ ]]` 标记，由程序按答对发放）。
- 答错：惩罚，扣 HP / SAN（数额由数值策划定，建议 10~20）。
- 每玩家每题**限答一次**；答错后该题对本玩家关闭，禁止反复试错刷题。
- **奖励限量**：每道题全局限前 N 名答对者发高价值物品（建议 N=3），之后答对只给小额物资。先到先得，晚到吃亏——这本身就是对抗性的一部分：谁先在探索上花时间，谁占便宜。

**机制标注（{} 统一说明，v1.3 起替代 [[ ]] 与独立 quiz 字段）：**

答题直接以 {} 标注在 result 末尾，题目、选项、规则三段式：

```
{答题:现在还有几个人活着？|选项:3,5,7,9|规则:dynamic_alive=存活人数，答题瞬间结算}
```

- 动态题规则类型：`dynamic_alive`（存活人数）/ `dynamic_room`（同房间人数）/ `dynamic_report`（当日通报次数）/ `dynamic_visit`（今日到访本节点的去重人数，含答题者本人，每天 0 点重置）——四者之一，禁止自创。
- `dynamic_visit` 的计数标准：第一个进入本节点的玩家计 1，此后每多一名到访者 +1，
  正确答案 = 答题瞬间的累计去重人数。选项要覆盖该节点的合理人流上限（低频场景用 1~4），
  真实人数超出选项范围则本题无解——所以到访题只放低频节点。
- 静态题规则写作：`规则:静态题，预设正确选项=第N项`。
- result 仍是出题那一刻的场景文本（15~60 字，遵守前五章全部铁律），标注跟在正文后面。

**出题要求：**

- 静态题要有"校园味"：可以是高数题、英语完形、校史冷知识、脑筋急转弯，禁止网上一搜就有答案的烂大街题。
- 动态题要有信息价值：答对等于免费获得一条 normally 要花钱/花 AP 才能查的局势信息（存活名单长度、房间里有没有人），答错白挨罚——这制造"要不要赌一把"的决策。
- 每 10~15 个 Y 节点最多挂 1 个答题节点，探索主基调仍是翻找物资，答题是点缀。
- quiz 节点和高价值掉落别埋在深度 4 以下的深链里：一天 10 AP 只够走一条深链，
  埋太深等于白写，深度 2~3 为宜（AP 上限后续由数值策划调整，写作按 10 AP 规划）。

## 八、对抗性增补约定（v1.2 定稿）

这一章是给"对抗性"补的课：文本不只服务氛围和物资，还要给玩家之间的推理供燃料，
同时绝不泄漏服务端才知道的信息。

### 1. 时间刻度词表（痕迹专用）

痕迹类描述必须落在下列刻度之一，同一事件链内口径一致：

| 刻度 | 用词示例 | 含义 |
|---|---|---|
| 极近（约 1 分钟内） | 还温着、冒热气、水汽没散、灰还没落回去 | 人刚走 |
| 本时段内 | 没干透、印子还新、绳结还没松、纸角还翘着 | 今天白天来过 |
| 上一时段或更早 | 凉了、结了层皮、印子起毛、褪成白色、积灰 | 不是现在的事 |

写痕迹时先想刻度再选词，禁止"既温着又积灰"这种自相矛盾的写法。

### 2. 痕迹纪律

- **对称性**：任何痕迹理事长也留得出来。禁止出现只有理事长才会留下的物证
  （袖章、值周记录、特殊钥匙痕），否则等于广播身份。
- **匿名性**：痕迹只证明"有人来过"，不证明"谁来过"。禁止能锁定身份的物证
  （写着全名的纸条、独一无二的所有物被留在现场）。
- **密度**：每个子位置（P）留 1~4 条痕迹即可，痕迹是味精不是主菜。

### 3. 位置断言禁令

文本**禁止断言其他玩家的实时位置、存在或身份**。"有个背影拐过弯""刚才有人来过
这间屋子""跑道上站着一个人"这类写法一律禁用——服务端才知道谁在哪儿，文本断言
了就是泄漏，断言错了就是出老千。涉及"看见人"的写法要么改成非断言的景物
（"跑道上有串脚印，还没干透"），要么整句删掉。

### 4. 幻觉同构

SAN 过低触发的幻觉文本，与真实文本**长得一模一样**：同样的句式、同样的口吻、
同样的长度，不排版标记、不文风突变。玩家只能靠交叉验证（监控、同行者证词、
二次查看）分辨真假——这是推理素材，不是 UI 测试。幻觉节点的占比和分布由
程序控制，创作方照普通节点写即可，只多一条：幻觉内容**违反现实但不违反文本风格**。

### 5. 空态文本（result_taken）

物资先到先得，来晚的人必须看到世界的反应。凡 result 中含 `[[掉落]]` 的 Y 节点，
除 result 外**必须**再写一条 `result_taken`（15~60 字，遵守全部铁律）：

- 落点是"扑空 + 痕迹"：东西没了，留下被翻动过的痕迹（时间刻度见词表）。
- 禁止复读原 result 再补一句"没了"，两条文本要各自独立成立。
- 扑空本身是情报——来者知道有人比自己先到、拿了什么品类。

```json
"Y9": {
  "choice": "别碰它，退开",
  "result": "你后退时踩到了什么。低头看，是一张旧饭票，面额栏里印着「明天」。（[[旧饭票]]）",
  "result_taken": "你后退半步。地上空空的，只剩一圈浅浅的压痕，像被谁抢先捡走了。"
}
```

程序判定：该节点掉落已被取走 → 显示 result_taken；未被取走 → 显示 result。

### 6. 重复访问约定（程序处理，写作须知）

一局多天，同一节点会被重复进入。约定：服务端记录玩家已读节点，重复进入时显示
程序拼装的短变体（"和昨天一样，哑铃还是缺那一个位置。"），不再播放完整 result。
因此写作时无需为复读做特殊设计，但每条 result 的**第一句必须是自包含的画面**，
不要出现"还是刚才那个""接着上文"这类依赖前文的写法。

### 7. 冲突道具

掉落池里固定 5~8% 给**冲突道具**（杠铃杆规矩已立项）：能对其他玩家起作用的
物理物品。**描述只写形态和手感，不写用途**——"沉甸甸的，一头粗一头细，握把上
缠着新胶布"，用不用来抡人、什么时候抡，让玩家自己决定。用途写明了是说明书，
不写才是给玩家的创造空间。冲突道具同样走 `[[ ]]` 标记，名字从 Wiki 选。

### 8. 时钟绑定禁令

文本禁止和游戏内时钟绑定的断言："现在是上课时间""第三节课还没下""天黑前"
这类写法禁用——玩家可能在任何时段读到它。想表达时间流逝，用不依赖时钟的
景物（"旗杆的影子挪了一指宽""开水房的水汽淡了"）。

## 九、机制标注与玩法覆盖（机制即文本）

### 1. {} 统一标注（v1.3 定稿，替代旧 【】 与 [[ ]] 写法）

事件涉及机制时，直接在文本里用半角 {} 标注，程序后续按此格式解析。五种标注：

| 标注 | 格式 | 示例 |
|---|---|---|
| 获得物品 | {获得:名称(段#编号)} | {获得:旧饭票(普#40)} |
| 状态改变 | {状态:行动值±n，饥饿值±n，健康值±n，精神值±n} | {状态:行动值-2，饥饿值-35，健康值+10，精神值+20} |
| 操作/界面 | {操作:说明} | {操作:打开背包选择物品回收} |
| 答题 | {答题:题目\|选项:A,B,C\|规则:类型=说明} | {答题:你是今天第几个来的？\|选项:1,2,3,4\|规则:dynamic_visit=今日到访本节点去重人数，含答题者本人，每日重置} |
| 动态注入 | {今日到访} | 程序替换为实时数字（白名单仅此一个） |

- 物品编号从《物品 Wiki》查：普=普通物品、高=高价值、关=关键道具、耗=消耗品，
  编号见 `output/wiki_index.json`。
- 标注只写机制，过程描写照常写在正文里；状态标注跟在 choice 末尾（玩家选前就看到代价），
  获得/答题标注跟在 result 末尾。
- 获得物品若可能被抢先取走（先到先得），仍按第八章第 5 节写 result_taken 空态文本。
- 旧写法 `[[物品]]`、`【效果】`、独立 `quiz` 字段一律废止，存量文本已批量转换。

### 2. 玩法覆盖树

树是起手稿不是合同。功能性场景（宿舍、食堂等）按实际玩法需要几个选项就写几个：
宿舍白天实际只有「睡一觉{状态:行动值-1，饥饿值-25，精神值+30，健康值+5}」一个事件选项，
那就只写这一个，不必为了填满树硬凑选项。同理，创作中想加节点就直接在文本里加（编号续排），
程序按文本实际结构解析。

## 十、写作准则：文本、结果、节点关系（v1.4，从学校大门迭代沉淀）

### 1. 文本（正文怎么写）

- **一句为主，加句须有职**：一句话说得清的绝不用第二句。第二句只许两种职务：
  一是**发现本身**（"你后退时踩到了什么。低头看，是……"——第二句是落点），
  二是**状态改变的理由**（"旗杆的影子挪了一指宽"{健康值+2}——没有这句，标注就是空降）。
  纯装饰性的尾句一律删。
- **每个事件都要有"结果感"**：选完不能什么都没有。要么拿到东西、要么付出代价、
  要么获得一条信息（动态数字、痕迹、对话内容）。纯氛围选项每场景至多留 2~3 个。
- **对话承担反馈**：有 NPC 的场景，对错、得失都先落在对话里（"眼熟。""下一个。"），
  标注跟在对话后面。NPC 说话要有性格，不要播音腔。

### 2. 结果（结算与标注）

- **机制必须闭环**：答题必有答对/答错两支，各带独立文本 + 效果；获得必有 {获得:}；
  代价必有 {状态:}。禁止"答完之后什么都没写"。
- **奖励要长在剧情里**：保安的奖励是报纸、抽屉里抛出来的是钥匙——物品从场景人物
  手里流出来，不凭空出现在地上。临时需要新物品就新增 Wiki 条目并标注编号。
- **全局唯一物品三件套**：限量奖励 = {答题…答对:获得…} + result_taken 空态
  （"来晚了。"）+ Wiki 数量标注；答错给"每日可重答"的退路，避免一次答错永久错失。
- **数值要敢给也给得起**：诡异事件 -3~-8 精神值、日常恢复 +1~+2，单次幅度小、
  可累积；别让任何一次点击动摇生死，动摇生死的是玩家长期不做事。

### 3. 节点关系（结构怎么组织）

- **机制节点挂在动作链上**：答题不是独立入口，而是动作触发的追问——"取下钥匙"
  这个普通动作引出保安提问。先让玩家做事，再让机制找上来。
- **一道题可以有多个入口、不同奖励**：同一道 dynamic_visit 题，取钥匙处答对给
  破旧钥匙，闲聊处答对给报纸。题目是场景的地基，奖励挂在入口上。
- **quiz 即终点**：带 {答题:} 的节点不再长出子选项，答完收束；后续动作另开节点。
- **文本增删节点自由，编号续排**：新增节点（人行道闸、讨水喝）从 max+1 编号，
  空间上必须属于本场景（闸机、传达室属于学校大门；别把咖啡屋塞进校门）。
- **树在场景写完后即作废**：campus_tree 只服务未创作场景的起草稿，写完即以
  campus_text 为唯一结构依据。
