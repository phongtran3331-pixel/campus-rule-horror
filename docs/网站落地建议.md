# 网站落地建议（《校园规则怪谈》实现路线图）

> 前提：贴图素材暂不配置，全部用程序化视觉（色块/渐变/CSS 光效）顶位。
> 文本数据已就绪：`output/<场景>/campus_text.json` 为最终结构依据，配 `output/wiki_index.json`（108 件物品）与 `docs/物品Wiki_原始.txt`（描述/价值/负重/效果）。

---

## 一、总体架构

```
浏览器客户端（手机竖屏 UI「自管委终端」）
    │  WebSocket（Socket.IO 省心：房间/广播/断线重连现成）
    ▼
Node.js 服务端（唯一权威状态机）
    ├── 房间管理（邀请码建房、在线人数）
    ├── 游戏状态机（日/阶段/时钟）
    ├── 违规判定引擎（规矩表驱动）
    ├── 经济系统（背包/货币/负重）
    └── 数据层：校园文本 JSON + Wiki + 规矩表（同仓库载入，改文案=改数据）
```

**关键决策：服务端只存状态与编号，不存文案。** 事件结果文案（`result`/`result_taken`）由客户端按场景 JSON 渲染，服务端只发「事件 Y3 命中、获得 普#5、状态变化」这类结构化结果。理由：文案迭代不用改服务端；理事长「假装交互」只需要服务端照常回结构、客户端照常显示。

## 二、数据契约（文本层 `{}` 标注 → 程序协议）

客户端渲染器写一个标注解析器，遇到标注就发对应请求/结算：

| 标注 | 服务端动作 |
|---|---|
| `{获得:名称(段#N)}` / 答题内 `获得物品:X(段#N)` | 背包 add；先查点位领取表（先到先得，领过回 `result_taken`） |
| `{状态:行动值-2，饥饿值-35，健康值+10，精神值+20}` | 四值结算（键只有这四个，固定正则可校验） |
| `{操作:...}` | 打开对应子界面（背包选择/货架/药品列表/校园墙…），**不直接结算** |
| `{答题:题\|选项:...\|规则:...\|答对:...\|答错:...}` | 弹出答题 UI；规则类型四种（见下） |
| `{今日到访}` | 客户端渲染时替换为服务端注入的实时数字 |

### 答题规则四种（程序各一行实现）
- `dynamic_visit`：本节点今日去重到访数（含答题者，每日 0 点重置）——服务器在玩家进入节点时计数
- `dynamic_alive`：当前存活玩家数
- `dynamic_room`：同节点实时人数
- `dynamic_report`：当日通报条数（违规事件+1 即更新）
- `静态题，预设正确选项=第N项`：配置直判

### result_taken（先到先得）
每个限量点位服务端记 `claimedBy`：被领过→回 `result_taken` 文案。每日刷新的点位（答题类）按日重置。

## 三、回合制时钟（服务端权威）

```
Day0（教学日）  Day1…Day4
├─ 上午 6min（探索，AP10）
├─ 中午 3min（自动传送食堂：讨论+投票，可选进餐）
├─ 下午 6min（探索）
├─ 傍晚 2min（21:00 前必须回宿舍，AP 归零强制传送）
└─ 夜晚（理事长：更换1条随机规则→按检举额度检举）
```
- 测试期探索时间已翻倍（上午/下午各 6min），上线前用沙盘参数回调。
- 时钟用服务端秒表广播 `{day, phase, remainSec}`，客户端只做倒计时显示——断线重连后按服务器校准，杜绝本地加速。

## 四、核心系统清单（按优先级）

### P0 可玩闭环
1. **房间/邀请码/身份分配**（9人局：6干事+3理事长，调试模式直接开局）
2. **地图节点移动**：`output/` 15 场景 situation 列表=节点树；移动按距离扣 AP（近1远2）
3. **探索渲染器**：进入节点→列 choice→点选→展示 result+结算→限量点位判定
4. **四值生存**：饥饿/日-33、低于40扣SAN、低于20扣HP、归零淘汰（玩法大纲数值表）
5. **夜间检举**：理事长报名字即可（不指认规则），成功 -25-5×day HP，额度=4+day→按「每有一人违规+1次」；错两次或用尽即止
6. **食堂投票**：讨论3min→投票→票最高者公示

### P1 对抗深度
7. **规矩引擎**：固定4条+每局随机抽N条；理事长每晚可换1条（从备选池替换，非反转）；违规→匿名通报（不显示哪条），理事长须自己记规则
8. **钥匙/锁体系**：破旧钥匙×4→社区四房间；储物柜钥匙（任意开一柜）；万能钥匙一次性；通行卡→行政楼门禁；剪刀/杠铃杆→网络中心（断网=全员失去玩家视野，4分钟自动恢复或1AP修复）
9. **经济三件套**：回收站（>5件随机SAN-1~-20）/超市双售货机/校医院贵价药房（价格已在文本标注）
10. **dynamic 答题**：四种规则查询接口 + `{今日到访}` 注入

### P2 社交与信息战
11. **聊天/私聊/转账/校园墙**（前台功能：破译2规则/三好学生表彰/匿名担保，每日三选一）
12. **档案调查**（办公室每日限1份：判2人同阵营）、**昨日预约记录**、**策创部抹规则**（理事长不可见）
13. **查询卡**：调阅机器日志（超商/图书馆/操场/社区闸机/影像室），只有时间+动作无人名——推理留痕
14. **理事长假装交互**：客户端不区分 UI，服务端对功能类操作回成功但不改状态；房间「查看物资」返只读清单（理事长特权）

## 五、界面顶位方案（无贴图）

- **地图**：CSS 网格坐标摆放场景名（无圆圈，纯文字+自定位青色光晕）；选中右侧弹卡片（描述+前往按钮）
- **节点界面**：色块分区+状态栏文字；恐怖氛围用暗色底+文字渐显+环境音（打字机音效已有）
- **背包**：网格 8×5（40格），图标先用首字色块，物品名悬浮显示；负重条
- **恐怖滤镜**：SAN 低于阈值加暗角/噪点 CSS 滤镜；断网模式全局降饱和+模糊——一张滤镜类实现，无需第二套素材

## 六、平衡与验收

- 数值全部集中在 `gameConfig`（服务端一个对象）：AP上限、检举公式、货价、回收价、四值衰减——调平衡只改配置
- 验收用调试模式跑 9 人模拟：理事长胜率目标 ~55%（沙盘推演报告口径），用物资丰度（掉落密度×价值系数）微调
- 每场景文本附带校验脚本（现有 python 校验器可进 CI：编号一致/答题闭环/状态格式）

## 七、部署

- 服务端 Node + Socket.IO 可放任意容器（此前已备好的服务器/主页体系挂子路径即可，如 `/campus`）
- 文本 JSON 与代码同仓库，发版即更新文案
