# **校园规则怪谈文游：教学楼 A 事件文本设计**

本次将教学楼 A 设计成一个具有完整探索层次、多个事件入口、分支选择、隐藏奖励和状态博弈的独立探索区域。

设计重点不是简单地让玩家进入房间、点击选项、获得物品，而是让每个地点都有自己的故事线索、人物互动和探索价值。玩家可以通过不同选择获得物品、改变状态、触发答题、消耗资源进行深度探索，甚至为后续其他场景解锁线索。

整体采用**场景节点 → 地点子节点 → 事件节点 → 分支结果 → 返回场景**的结构。

### **2. 统一事件结算规则**

以下所有事件均采用统一的结算结构，便于程序端直接配置。

| 类型   | 结算规则                      |
| ---- | ------------------------- |
| 获得物品 | 每个事件结局最多获得 1 件物品          |
| HP   | 生命状态，单次变化 -30～+30         |
| SAN  | 精神状态，单次变化 -30～+30         |
| HUG  | 饥饿状态，正数代表更饥饿，负数代表饥饿缓解     |
| AP   | 探索行动点，普通探索不修改             |
| 货币   | 使用游戏内通用货币，具体数值由系统配置       |
| 深度探索 | 需要额外消耗 AP、货币或满足物品前置条件     |
| 答题事件 | 由系统根据场上玩家信息生成问题，不在文本中写死题目 |
| 事件结束 | 所有结局均返回教学楼大厅，不自动退出教学楼     |

**重要设计约束：**

1. 每个地点可以重复进入，但同一个一次性奖励事件不可重复领取。
2. 已完成的普通事件可以显示已探索状态，避免无限刷取物品。
3. 深度探索属于独立事件入口，不应因为完成普通探索而自动解锁，必须满足指定条件。
4. 答题事件的正确与错误结果均需要独立配置，不能只设置正确答案奖励。
5. 状态值变化均采用增量结算，最终状态由系统限制在各自允许范围内。
6. 同一个分支只结算一次，不允许同时触发两个结局。
7. 高价值物品、关键物品与普通物品要区分投放，避免普通地点直接大量产出稀有资源。

黑板上残留着上节课没有擦干净的板书。最后一排有一张桌子被单独拉开，桌面上刻着几个模糊的数字。

你注意到讲台、课桌和教室后方的储物柜似乎都留下了可以调查的痕迹。

**地点交互选项**

- A. 检查讲台。
- B. 翻找最后一排的课桌。
- C. 检查教室后方的储物柜。
- D. 仔细观察黑板上的残留字迹。

### **Y[10101]：检查讲台**

**动作文本**

你走到讲台前，伸手拨开堆积的粉笔灰。

讲台抽屉没有上锁，里面散落着几截粉笔和一张被揉皱的纸。

你将纸摊开，发现上面似乎是某位老师随手记录的课堂安排。

**分支选择**

| 选项        | 文本与结果                               |
| --------- | ----------------------------------- |
| A. 收集剩余粉笔 | 你将几截尚能使用的粉笔装入口袋。获得「半截粉笔」普#1。        |
| B. 仔细阅读纸张 | 纸上写着一段没有署名的课堂记录。SAN -2，获得「旧值日表」普#2。 |
| C. 不再停留   | 你将抽屉推回原位，离开讲台。无物品，无状态变化。            |

所有分支结束后返回 P[A0]。

### **Y[10102]：翻找最后一排课桌**

**动作文本**

最后一排的桌面比其他位置更加干净。

桌肚里塞着一本旧课本，书页边缘被反复翻动过。你抽出课本时，一张小纸片从书页中滑落。

## **七、游戏逻辑策划端需要注意的细节**

### **1. 物品投放平衡**

建议将物品分成以下几种投放等级：

| 物品类别     | 投放策略              |
| -------- | ----------------- |
| 普通物品（普）  | 普通探索的主要奖励，分散投放    |
| 高价值物品（高） | 主要放在三楼、深度探索和特殊分支  |
| 关键物品（关）  | 通过前置条件、答题和深度探索获得  |
| 消耗品（耗）   | 主要分布在实验室及其他资源补给地点 |

这里尤其要注意：**高价值物品不能在所有分支中无条件获得。**

例如 P[203] 的名牌钢笔、P[303] 的蓝牙耳机，都应当设置一次性领取标记。不同玩家可以探索不同分支，但同一个玩家不能通过反复进入房间无限刷取同一件奖励。

### **2. 状态变化建议**

| 状态  | 普通事件  | 高风险事件  | 正确答题      | 错误答题      |
| --- | ----- | ------ | --------- | --------- |
| HP  | -3～+3 | -10～-2 | 0～+5      | -10～-2    |
| SAN | -5～+5 | -15～-3 | +3～+8     | -15～-5    |
| HUG | -3～+3 | +3～+8  | 0         | +2～+5     |
| AP  | 不变    | -1     | -1（仅深度探索） | -1（仅深度探索） |

以上是数值设计区间，并非每个事件都必须改变状态。最终变化量仍由各分支配置决定。

### **3. 推荐的事件数据结构**

沿用场景 X、地点 P、事件 Y 的编号方式，建议每个事件在程序中保存以下字段：

| 字段             | 含义               |
| -------------- | ---------------- |
| event_id       | 事件唯一编号           |
| parent_id      | 所属地点编号           |
| event_type     | 普通探索 / 深度探索 / 答题 |
| prerequisite   | 前置条件             |
| action_text    | 玩家触发事件时的描述       |
| options        | 玩家可选行动           |
| result_text    | 选择后的叙事文本         |
| item_reward    | 获得的物品，最多一个       |
| state_delta    | HP/SAN/HUG/AP 变化 |
| currency_delta | 货币变化             |
| consume_items  | 消耗的前置物品          |
| unlock_events  | 解锁的后续事件          |
| repeatable     | 是否允许重复触发         |
| return_node    | 事件结束后返回的地点       |

**编号建议：**

- X[A]：教学楼 A 主场景。
- P[101]～P[104]：一楼地点。
- P[201]～P[204]：二楼地点。
- P[301]～P[304]：三楼地点。
- Y[10101] 等：普通事件。
- Y[10105] 等：深度探索事件。
- Y[90001] 等：跨地点隐藏事件。

### **4. 必须明确的程序执行顺序**

```
进入教学楼 A
    ↓
显示教学楼大厅
    ↓
玩家选择楼层及地点
    ↓
检查地点是否开放
    ↓
显示地点场景文本
    ↓
玩家选择事件入口
    ↓
检查事件前置条件
    ↓
显示事件动作文本
    ↓
玩家选择分支
    ↓
检查资源及物品是否满足
    ↓
执行分支结果
    ├── 发放物品（最多一个）
    ├── 修改 HP / SAN / HUG
    ├── 修改 AP
    ├── 扣除货币
    ├── 消耗前置物品
    └── 解锁后续事件
    ↓
更新事件完成状态
    ↓
返回教学楼大厅
```

特别提醒：答题事件需要在进入答题前锁定本次事件状态，避免玩家通过重复提交答案刷取奖励；答题正确与错误都必须有明确的结算路径。

**整体设计定位：** 一楼负责基础物资和线索收集，二楼负责信息验证与关键物品获取，三楼负责高价值资源和特殊区域探索。玩家可以自由选择探索顺序，但部分深层内容需要通过前面获得的物品和信息才能解锁。
